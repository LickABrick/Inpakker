# v0.7.0

## Highlights

- Routine inventory browsing uses metadata-based build-state hints; exact
  verification remains available on demand and builds still verify content.
- The application list presents one primary status, with validation problems
  taking precedence over build state.
- Routine success returns to the page with a quiet completion hint, with details
  and logs available through **Last result** (`L`).

## Performance

- Inventory refresh shares discovery, application snapshots and inspection state
  within an operation instead of repeating configuration and cache reads.
- Fast refresh inspects metadata without reading source or packaging-tool file
  contents. Matching evidence can reuse an earlier exact inspection for display.
- Optional `inspection-evidence.json` provides a regenerable user-local index,
  separate from successful build records. Missing or unusable evidence does not
  prevent exact inspection or packaging.
- Content fingerprinting reuses the packaging-tool digest within a batch while
  hashing each application's source independently.
- Filtering reuses snapshot search and identity indexes; operation results update
  affected applications without rescanning unrelated applications.

These are implementation changes, not measured speedup claims. No performance
measurements are included in these notes.

## Terminal UI

- `r` performs a fast inventory refresh. **! Verify state** indicates that an
  exact inspection is needed, not that the application necessarily changed.
- Open `:` and choose **Verify all build states** to read content and establish
  exact evidence for the complete inventory, including filtered-out applications.
- Preview and details retain validation, build and package information without
  adding competing status columns to the list.
- Bulk build, validation and unpack actions show their complete-inventory count;
  filtering does not narrow their scope.

## User experience

- Successful routine operations no longer require dismissing a success dialog.
  Last result retains session-local details and available tool output; failures
  and cancellation still receive explicit feedback.
- Ordinary application scaffolding creates directly after form submission.
  Selecting an external installer to copy still opens **Review application**
  with the source and resolved destination before writing.
- The Group field determines creation location; the current list filter is not
  a creation destination.

## Developer experience

- Keyboard, contextual actions and palette commands share semantic action
  dispatch rather than manufacturing keyboard events.
- Cancellable fingerprint and inventory APIs keep filesystem work outside
  rendering and preserve workspace/request identity when applying results.
- Inspection and inventory benchmark fixtures expose file/content work without
  making their execution or results a prerequisite for reading these notes.

## Fixes

- Superseded refresh requests are cancelled and filesystem refresh work is
  serialized; stale workspace/request results cannot replace newer inventory.
- Filtering and responsive list rendering reuse snapshot indexes and preserve
  application selection where the target remains available.
- Local inspection evidence cannot replace content hashing when deciding whether
  a normal build can skip packaging.

## Compatibility

- Portable workspace/application configuration and successful build-cache
  contracts are unchanged. Inspection evidence is separate machine-local state.
- Normal builds skip only when exact input fingerprints match successful build
  state and the expected output exists. `--force` rebuilds; `--no-cache` bypasses
  build-cache and inspection-evidence reads and writes.
- Windows AMD64 remains the supported product target. Packaging still uses
  Microsoft's external Content Prep Tool; the decoder remains optional.

## Upgrade notes

- No portable configuration migration is required. Inspection evidence is
  optional and can be regenerated; it is not a package or successful-build record.
- After upgrading, **! Verify state** can appear until exact evidence is available.
  Use **Verify all build states** from `:` or run a normal build for an exact
  skip/build decision. `r` deliberately remains a metadata-based refresh.
- A browsing hint is not proof of content equality: edits preserving file size
  and modification time can evade metadata checks. Builds still hash content.
- Use `L` to inspect the last routine operation rather than expecting every
  successful operation to open a dialog. Result history ends when the TUI exits.

These notes describe implemented behavior; they do not assert that release
verification, tagging, artifact signing or publication has occurred.
