# v0.7.0 — release preparation

These notes describe the v0.7.0 target and are a draft, not a release announcement.
Final inclusion depends on implementation review and passing the release gates.
No measured performance improvement is claimed.

## Inventory and build-state inspection

- Keep inventory refresh cancellable and tied to its originating workspace and
  request. Superseded work must not replace newer results.
- Use metadata-based inspection for routine browsing, reserving content hashing
  for exact inspection and build decisions. Matching file sizes and modification
  times are a hint, not proof that source bytes are unchanged.
- Keep optional inspection evidence in regenerable user-local state, separate
  from successful build records and portable workspace configuration. Missing or
  unusable evidence must not prevent authoritative inspection or packaging.
- Preserve exact build semantics: normal builds may skip only when content
  fingerprints match successful build state and the expected output exists;
  `--force` rebuilds; `--no-cache` bypasses local cache reads and writes.

## Terminal workflow

- Present one primary application status in the list: validation problems take
  precedence over build state. Keep richer validation/build information in the
  selected application's preview and details.
- Keep successful routine operations quiet while retaining their results and
  logs behind **Last result** (`L`). Failures, warnings and cancellation still
  need visible feedback.
- Make application creation scope explicit: the Group field determines the new
  application's location; a list filter is not a creation destination. Review
  resolved paths before writing files.

## Compatibility and release review

Portable workspace/application configuration remains separate from local
inspection evidence. There is no change to the supported Windows AMD64 target
or to the requirement for Microsoft's external Content Prep Tool.

Before publication, reconcile these notes with the final implementation and
confirm CI, Windows smoke coverage and release artifact integrity. Release
preparation does not mean that a tag, signed artifacts or a GitHub Release have
been published.
