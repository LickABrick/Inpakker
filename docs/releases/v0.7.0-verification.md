# v0.7.0 verification measurements

Measured during the consolidated verification phase on Linux AMD64, Intel Core
 i5-1335U, using the Go toolchain selected by `go.mod`. These are local development
measurements, not Windows throughput guarantees. Each number is the median of
three `-benchtime=100ms` runs. OS filesystem caches were not flushed; “cold” means
no inspection evidence, not cold storage.

The 100-application fixture contains 10,682,386 source bytes, including one 4 MiB
payload and 99 generated 64 KiB setup files. The old measurement at `aa94433`
executes the former full refresh work (`inspectApplications`, `Groups`, `Diagnose`).
The new snapshot benchmark includes discovery, groups, application inspection,
shared build-state inspection and snapshot diagnostics. Command scheduling and
terminal painting are excluded from both inventory measurements.

| Scenario | v0.6.1 | v0.7 implementation | Change |
| --- | ---: | ---: | ---: |
| Cold inventory, 100 apps | 42.008 ms | 8.601 ms | 79.5% less time |
| Warm inventory, 100 apps | 55.713 ms | 9.029 ms | 83.8% less time |
| One changed app, normal inventory | 64.011 ms | 11.821 ms | 81.5% less time |
| 500 rows, width 120, rebuild + render | 7.147 ms | 5.152 ms | 27.9% less time |
| 500 rows, width 120, render only | 0.493 ms | 0.521 ms | 5.7% more time |

Normal cold/warm/changed inventory reports **zero source content hash bytes, zero
source hashes and zero utility hashes**, measured by context-scoped counters at
the actual hashing call sites. Each 100-app snapshot observes 101 source-file
metadata entries. Authoritative inspection reads all 10,682,386 source bytes and
hashes the utility once per inspection context. The authoritative algorithm and
cache-skip contract are unchanged; the fast state deliberately offers less
certainty than full content verification.

Additional runs cover 10, 100 and 500 applications, metadata versus authoritative
fingerprints, and table widths 60, 90 and 120. Timing varies with system load;
the zero-content-read contract is enforced by regression tests rather than timing.

## Local checks

Full tests (`-count=1`), vet, build and full race tests (`-race -count=1`) passed
using `CC=/usr/bin/gcc`. The environment's default `/usr/local/bin/gcc` wrapper
failed compiling Go's C runtime; the system compiler resolved that environment
issue without repository or dependency changes.

Automated model/render tests cover UI interactions and responsive layouts. No
human interactive terminal walkthrough or execution of Microsoft's real packaging
tools was performed in this Linux session. Windows tests and isolated PowerShell
installer/uninstaller checks are enforced by the unchanged GitHub CI workflow.

Release status and remote CI outcomes are reported separately; this document is
not a claim that signed artifacts have been published.
