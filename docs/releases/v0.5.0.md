# Inpakker v0.5.0

This release makes common TUI actions easier to find and keeps operation results
and recovery in dialogs over the page where the work started.

## New workflows

- Press `a` on Applications, application details or an operation result to open
  its available actions. Existing keyboard shortcuts continue to work.
- Builds and unpacking offer tool setup directly when their required executable
  is missing or unavailable. Settings also exposes official downloads and existing
  executable selection. Downloads require acceptance of upstream license terms.
- Press F2 during application creation to choose an installer to copy into the
  new source directory. Review the application, source, setup and output paths
  before creating it, or return to editing without losing the draft.
- Scripts can use `inpakker new "App Name" --setup-from "C:\Downloads\setup.msi"
  --no-input`. Only the selected file is copied; add companion files separately.
- Open package output from the CLI with `inpakker open "App Name" --output`.

## Dialog and operation improvements

- Save/create controls show a single label with a clear focus state. New
  applications use one optional group field with existing-group suggestions.
- Build, validation, unpack, tool installation and update results stay in
  scrollable dialogs. Status text and tool-output severity use semantic colors
  with text labels, so state does not depend on color alone.
- Cancellation waits for the operation to stop and preserves completed results.
- Quiet TUI builds retain the last 256 KiB of diagnostic output for inspection.
- Result actions open output folders and retry only failed applications with
  their original build options. `L` reopens the last result during the session;
  workspace results remain tied to their originating workspace.
- Tool downloads show installation phases and received bytes, with percentage
  progress when the upstream supplies a total size.
- Boolean settings use On/Off controls. Directory values are validated before
  saving, and failed setting saves preserve the entered value for retry.
- Explicit update checks and installation remain available when automatic
  update checks are disabled.

## Compatibility

Windows AMD64 remains the supported release target. This is an additive release:
there are no configuration schema changes or migrations from v0.4.0. Existing
workspaces, application identities and build caches continue to work. The v0.4
replacement of v0.3 configuration formats remains unchanged.
